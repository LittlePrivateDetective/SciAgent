# 主模型切到 qwen-flash 的实测记录

> 2026-11-12 01:25 · 对应配置：`.env` 的 `LLM_MODEL=qwen-flash`（原 `deepseek-v4.1-flash`）
> 只换主对话模型；翻译 / 写作 / 重排 / 向量化本来就是 qwen 系，未变。

## 一、为什么换

DeepSeek 带思维链，回答更完整，但**慢**：一次 RAG 问答 18–36 秒。演示时问完要等半分钟，评委的注意力已经跑了。qwen-flash 是项目里翻译和写作一直在用的非推理模型（120+ tok/s），换成它主要是换"等待时间"。

## 二、同一批问题的对照

3 条真实库内问题（Attention Is All You Need / BERT / Mistral 7B），非流式 `/api/chat`：

| 问题 | deepseek-v4.1-flash | qwen-flash（首次） | qwen-flash（热态） |
|---|---:|---:|---:|
| 多头注意力的计算复杂度 | 31.6 s | 25.5 s | 7.7 s |
| BERT 与 GPT 的预训练目标差异 | 18.3 s | 7.5 s | 8.1 s |
| Mistral 7B 的推理优化技术 | 35.9 s | 6.2 s | 7.0 s |
| **合计** | **85.8 s** | 39.2 s | **22.8 s** |

热态后 **3.7 倍**。第一次那 25.5 秒是 qwen 侧的连接与检索缓存同时冷启动，不是模型慢。

流式（前端实际走这条）：感知延迟 0.08 s 就开始出思考阶段，**2.6 秒**出完 357 字正文。

## 三、质量：能用，但细节会掉

**没有幻觉、引用照旧可验证。** 锚点校验（`verify`）三道题分别是 5/5、6/6、3/3，`rate=1.0`，`bad_numbers` 为空——也就是说每一条 `[n]` 都能落回原文页与坐标。

但深度上有差别，两个典型：

- **公式型问题**：问"多头注意力复杂度是多少"，DeepSeek 直接答 `$O(n^2 \cdot d)$`；qwen-flash 只答"与全维度单头注意力相似"，然后才给出 `$d_k = d_v = d_{model}/h$`——**没把总复杂度写出来**。前者是答案，后者是解释。
- **列举型问题**：Mistral 7B 那题，DeepSeek 列了 GQA / SWA / rolling buffer cache / pre-fill；qwen-flash 只列 GQA / SWA，少了两项（虽然都在同一段证据里）。

**工具调用正常。** "搜一下 2023 年关于稀疏注意力的论文" → 正确走 `llm_function_call`，选 `arxiv_search` 并传 `query="sparse attention"`（18.4 s，含首次建连）；无关问题走关键词兜底，不硬编。

## 四、一个反直觉的点：思考过程没受影响

顶栏和消息上方的"思考过程"（任务规划 / 检索 / 定位证据）**不是模型的思维链**，是后端管线自己发的阶段事件。所以换掉带 CoT 的 DeepSeek 之后，这部分展示完全不变——原来担心的"演示里少了一块"并没有发生。

## 五、结论与建议

| 场景 | 建议 |
|---|---|
| 演示 / 现场问答 | **用 qwen-flash**：3.7 倍速度，观众不用干等 |
| 需要精确公式、完整列举 | 用 deepseek：回答更全，代价是慢 |
| 交付文档里的性能数字 | 两个都写，说明这是"速度 vs 深度"的显式取舍，而不是"哪个更好" |

改回 DeepSeek 只需把 `.env` 的 `LLM_MODEL` 改回去并重启，或在后台参数中心直接改（热生效）。

## 六、附带发现（未修）

前端**没有 KaTeX**，模型输出的 `$O(n^{2}·d)$` 会原样显示成美元符号包裹的源码。这个问题与换模型无关（DeepSeek 输出同样是 LaTeX），但 qwen-flash 的回答里公式更密集，所以更显眼。见缺陷表 D-66。
