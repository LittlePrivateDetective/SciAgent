## 一、需求理解

赛题本质不是"做一个文献问答机器人"，而是**在真实科研场景里证明 Agent 的必要性**。原文三句话定了调：

1. "**输入素材可审查**"——必须吃得住学术标准 PDF 与扫描件；
2. "**输出成果可验证**"——解析结果、问答溯源、图谱节点、代码与绘图脚本、综述文本，**均需具备确定性、可被交互验证**；
3. "**系统运行闭环**"——要有完整前后端 + 全流程贯通。

翻译成工程语言：**每一个 LLM 输出都必须带一个"人可点开核对"的锚点**。这是本项目的胜负手，也是后面所有设计的原点。

评分权重（官方原文，四项合计 100%）：

| 维度 | 权重 | 关键子项 |
| --- | --- | --- |
| Agent 与大模型技术深度 | **35%** | 编排 9 / 抗幻觉溯源 8 / 文档解析 7 / Function Calling 6 / Prompt+Guardrails 5 |
| 科研场景创新性 | **25%** | **图谱挖掘 10** / RAG 与去重创新 8 / 科研交互模式 7 |
| 全栈工程质量与系统鲁棒性 | 10% | 代码质量 4 / 可复现部署 3 / 渲染性能 3 |
| 科研实用性与业务闭环 | 10% | 痛点契合 5 / 测试用例通过率 5 |
| 学术级 UI/UX | 10% | 界面 4 / 联动阅读 3 / 流式思考 3 |
| 学术价值与应用广度 | 10% | AI4S 价值 5 / 开源潜力 5 |

**结论：42 分（编排 9 + 溯源 8 + 解析 7 + 图谱 10 + 去重 8）是"可被专家当场验证"的硬分**，必须做实。剩下的分靠"覆盖 + 诚实 + 部署活着"。

### 2.2 为什么要"中央编排 + 专家 Agent"，而不是一个大 prompt

三个可答辩的理由：

1. **上下文隔离**。审稿 Agent 只需要"草稿 + 引用清单"，不需要看 20 篇 PDF 原文；阅读 Agent 只需要单篇。单 Agent 会把所有东西塞进一个 context，长文场景必炸（541 页《Understanding Deep Learning》是官方用例）。
2. **可重规划**。解析失败 → 转 OCR；检索为空 → 拆子问题重查；代码报错 → 读 stderr 修代码。这些分支写在图里是**显式的**，写在 prompt 里是靠模型自觉，评审问一句"你怎么保证"就穿。
3. **可测**。每个节点是纯函数（state in → state out），`eval/` 能对单节点打分，而不是黑盒打分。

### 2.3 LangGraph 状态机（核心）

```

                     │ START                       │
                     └──────────────┬──────────────┘
                                    ▼
                          ┌──────────────────┐
                          │ planner 分解任务  │◄────────────┐
                          └────────┬─────────┘             │
                                   ▼                       │
                       ┌───────────────────────┐           │
                       │ 判断 step 类型 → 路由  │           │
                       └──┬───┬───┬───┬───┬───┬┘           │
            ┌─────────────┘   │   │   │   │   └────────┐   │
            ▼                 ▼   │   ▼   │            ▼   │
       ┌────────┐      ┌────────┐ │┌───────┐│    ┌──────────┐
       │reader  │      │retrieve│ ││analyst││    │ writer   │
       └───┬────┘      └───┬────┘ │└───┬───┘│    └────┬─────┘
           │               │      │    │    │         │
           └───────────────┴──────┴────┴────┴─────────┘
                                   ▼
                          ┌──────────────────┐
                          │ reviewer 质检     │
                          └────────┬─────────┘
                                   ▼
                     ┌──────────────────────────┐
                     │ pass?  ──否──► 重新规划  │──┐
                     │   │是                    │  │ 回 planner
                     │   ▼                      │◄─┘
                     │ reflector 反思+写记忆     │
                     └──────────┬───────────────┘
                                ▼
                              END
```

State 定义（`SciState`）：

```python
class SciState(TypedDict):
    task_id: str            # 任务 ID（可回溯）
    goal: str               # 用户原始意图
    plan: list[Step]        # Planner 产出的 DAG 平铺
    cursor: int             # 当前步
    doc_ids: list[str]      # 本次任务涉及的文献
    evidence: list[Anchor]  # 累积证据（锚点）
    draft: str              # 中间产物
    artifacts: dict         # 图表/图谱/导出文件路径
    retries: int            # 重试计数（>2 强制降级）
    reflections: list[str]  # 本轮反思
    trace: list[dict]       # 全链路 trace（答辩演示用）
```

## 三、Agent 职责与 Prompt 设计要点

| Agent | 职责 | 输入 → 输出 | 关键约束（Guardrails） |
| --- | --- | --- | --- |
| **Planner** | 任务分解为 3–7 步 DAG，选工具，失败时重规划 | goal + 文献清单 + 历史经验 → `Step[]` | 只允许调用已注册工具白名单；步数上限 12；必须给每步标"可验证产出" |
| **Reader** | 单篇结构化：标题/作者/机构/摘要/章节树/图表/公式/参考文献 | pdf → `PaperCard` JSON | 一级/二级标题必须来自解析树，**不许模型编**；摘要原样摘录不许改写 |
| **Retriever** | 混合检索 + 重排 + 锚点返回 | query → `Anchor[]` | 召回不足 3 条时**明确说"文献库没有"**，禁止用常识补 |
| **Analyst** | 写 Python 做统计/清洗/绘图 | 数据 + 分析意图 → 代码 + 图 + 结论 | 代码在子进程沙箱跑（禁网、限 30s、限内存）；图必须落地为文件 |
| **Writer** | 综述/章节/翻译/GB/T 7714 | 证据 + 大纲 → Markdown | 每个陈述句后必须挂 `[doc p.x]`；无证据句自动标 `【待补】` |
| **Reviewer** | 逻辑/结构/引用/格式四查 | 草稿 → 问题清单 + 分数 | 只能基于原文与草稿判断，输出必须给"改哪一句、改成什么" |
| **Reflector** | 评估本次任务质量，抽经验写长期记忆 | trace + 结果 → `Lesson` | 经验必须结构化（场景/错误类型/修正动作），可被检索复用 |

**Prompt 工程统一约定**（对应 5% 的 Prompt/Guardrails 分）：

- 所有 Agent 共用一段 `SYSTEM_CONTRACT`：角色 + 输出 JSON Schema + "不确定就说不确定" + "禁止编造页码"。
- 输出全部走 JSON 模式（`response_format={"type":"json_object"}`），解析失败自动重试 1 次，再失败降级为纯文本 + 后处理。
- 中文回复、术语保留英文原词（GB/T 术语规范）。

## 四、技术选型与理由

| 层 | 选型 | 理由 | 备选（不选的原因） |
| --- | --- | --- | --- |
| 编排 | **LangGraph** | 赛题点名；显式状态机 + conditional edge 正好演示"动态重规划"；图即文档，答辩可直接放 | LangChain AgentExecutor（黑盒、难演示重规划） |
| 后端 | **FastAPI + SSE** | 流式输出、异步、自带 `/docs`；复用你已有经验 | Flask（无原生 async） |
| 向量库 | **Chroma（PersistentClient）** | 赛题点名、本地免部署、支持 metadata 过滤（按 doc_id 过滤是溯源必需） | Milvus（要部署服务，8 天不划算） |
| 前端 | **自研静态页（原生 JS + PDF.js + ECharts）** | 零构建链、单容器即可部署、能直接画 bbox 高亮框；PDF.js 是官方推荐 | React+Next（构建链 + 3 天成本，个人赛性价比低）；Gradio（画不出原文框选，"锚点"这个核心卖点就没了） |
| 检索 | **BM25（rank_bm25）+ 稠密向量 + RRF 融合 + 重排** | "混合检索（Dense/Sparse）策略是否合理"是 8% 的明写考点 | 单一向量检索（专有名词、公式符号召回差） |
| 切块 | **结构化切块**（按章节树 + 600 字滑动窗口，保留 bbox 并集） | 比固定窗口的溯源精度高一个量级 | LangChain RecursiveCharacterTextSplitter（丢版面信息） |
| PDF 解析 | **PyMuPDF（已有）** + `get_text("dict")` 级别坐标 | 你已踩通双栏；坐标级 bbox 是锚点的前提 | MinerU/unstructured（重、慢、装不上风险） |
| OCR 兜底 | **多模态 API 兜底**（Qwen-VL / GLM-4V，可配）+ 本地 PaddleOCR 可选 | 无文本层的扫描页才走 OCR，量小；不引入重依赖 | 只上 PaddleOCR（paddle 安装风险高，8 天赌不起） |
| LLM | **任意 OpenAI 兼容**（默认 DeepSeek-chat） | 满足"禁止绑定单一厂商"，`.env` 配 base_url/key/model 可换 Qwen/GLM/Ollama | 绑死单一 SDK |
| Embedding | **OpenAI 兼容 `/embeddings`**（默认 bge-m3，可切本地 sentence-transformers） | 与 LLM 同源配置，零额外部署；留本地兜底 | 强制本地大模型（2060 6G 跑 bge-m3 可以，但下载+推理拖时间） |
| 存储 | **SQLite（WAL）** | 零部署、单文件可交付、支持事务 | Postgres（多一个容器，评审复现成本↑） |
| 图算法 | **NetworkX** | PageRank / betweenness 现成 | igraph（同上，够用即止） |
| 部署 | **Docker + Caddy + （可选）Cloudflare** | 一键复现是 3% 明写分；Caddy 自动 HTTPS | 裸 gunicorn（证书/反代要自己写） |

**成本预估**：开发 + 跑官方用例 + 录视频，8 天约 ¥20–50（DeepSeek 便宜，embedding 用免费额度）。全程不依赖付费专有服务。

## 六、数据设计

### 6.1 SQLite 表（8 张，够用即止）

```sql
documents(id, family_id, title, authors, year, venue, arxiv_id, doi,
          file_path, pages, char_count, version, content_hash, simhash,
          is_scanned, status, created_at)
-- family_id: 同一论文的不同版本归为一族（v1/v7 去重靠它）

       token_len, order_idx)
-- bbox 是锚点的物理载体；section_path 如 "3.2/3.2.1" 用于标题树导航

-- matched_by: doi / arxiv / title_fuzzy，便于答辩解释匹配策略

           status, error, latency_ms)
-- ★ 每步落库 → 前端 trace 回放 → 答辩演示"Agent 真的在分步执行"

-- ★ 反思经验库；hits 计数即"自主进化"的量化证据

```

### 6.2 锚点协议（全项目的中心契约）

```
[p{page}@{x0},{y0},{x1},{y1}]
示例：[p3@120,480,468,512]
```

三个环节强绑定：

1. **产出**：`chunks.bbox` = 合并块包围盒并集（已实现）；
2. **引用**：LLM 被要求只能引用检索结果里的 `chunk_id`，服务端把 chunk 换成锚点字符串渲染——**不让模型自己编坐标**；
3. **校验**（`rag/anchors.py::verify`）：
   - 锚点必须能在该 doc 的 chunks 里找到（页码 + bbox 容差 2pt 命中）；
   - 找不到 → 判定幻觉 → 触发一次"带证据重答"，二次失败则输出"依据不足"。
   - 校验通过率进 `eval/report.md`，作为抗幻觉的量化指标。

> 这条链路是 8% 溯源分 + 5% Guardrails 分的实体。答辩必讲。

### 6.3 语义去重（官方用例 3.1，8%）

三层判定，逐层短路：

| 层 | 方法 | 阈值 | 作用 |
| --- | --- | --- | --- |
| 1 | 文件名 / arXiv ID / DOI 归一 | 精确 | 抓 1706.03762v1 vs v7 |
| 2 | **SimHash**（正文归一化后 64 位，汉明距离） | ≤ 6 | 抓同文不同文件名的搬运 |
| 3 | **摘要向量余弦** | ≥ 0.92 | 抓改了标题/排版的变体 |

命中后行为（对应官方"预期行为"）：
- 主动弹窗："库中已有内容高度重合的文献（v7，更新）"；
- 三选一：**覆盖 / 保留两份 / 放弃上传**；
- 若版本号可解析且新版本更高 → 默认建议"保留更新版本"，并提示"是否对比差异"；
- **版本差异摘要**：按章节树对齐两版 chunk，定位"新增/删除/改写"段落，输出一页 diff 报告。

### 6.4 引用图谱（10%，最高子项）

流程：

```
参考文献列表（Reader 抽出 raw_text）
   → 归一匹配：DOI > arXiv ID > 标题模糊(rapidfuzz, ≥92)
   → 命中库内文献 → 建边；未命中 → 存为"外部节点"（灰点，可后续下载）
   → NetworkX DiGraph
   → PageRank（基石论文）+ betweenness（桥接论文）+ in-degree（被引最多）
   → 前端 ECharts graph 渲染，节点大小=PageRank，颜色=聚类
```

**Future Work 综述生成**（官方点名）：
1. 抽取每篇的"Future Work / Limitations / Conclusion"段落；
2. 按主题聚类（embedding + 层次聚类）；
3. 与"已被后续论文解决的问题"对撞：若某 Future Work 在引用它的更新论文中出现对应方法段 → 标 `已解决`，否则标 `仍开放`；
4. 输出"研究时间线 + 开放问题清单"。

> 这一步是"自动化掉已被后续论文解决的旧 idea"的落地点，也是创新分 10% 的答辩硬货。

### 6.5 文件与缓存策略（3% 性能分）

- PDF 原文件 `data/uploads/{doc_id}.pdf`；页图 `data/pages/{doc_id}/{page}.png`（144dpi，**按需渲染 + LRU 上限 200 张**）；
- 2C2G 机器上整篇渲染必 OOM，故：只渲染被引用的页、并发上限 2、导出图片走流式；
- 541 页长书：解析分页流式入库（每 20 页 flush 一次 chunk），不整本驻留内存。

```env
# LLM（任意 OpenAI 兼容）
LLM_BASE_URL=https://api.deepseek.com/v1

EMB_DIM=1024

# 检索
TOP_K=8  RERANK_TOP_N=4  CHUNK_MAX_CHARS=600

# 运行
DATA_DIR=./data  MAX_UPLOAD_MB=100  SANDBOX_TIMEOUT=30
```

三个推荐默认（按"能跑通 + 便宜 + 不绑厂商"排序）：

| 用途 | 默认 | 备选 | 说明 |
| --- | --- | --- | --- |
| 对话/写作 | DeepSeek-chat | Qwen-plus / GLM-4 / 本地 Ollama(qwen2.5:7b) | 中文强、价格低、OpenAI 兼容 |
| Embedding | 硅基流动 bge-m3（免费额度） | 本地 `BAAI/bge-m3`（2060 可跑）/ text-embedding-3-small | 中文论文效果明显优于 OpenAI 小模型 |
| 扫描页 OCR | Qwen-VL-max | GLM-4V / 本地 PaddleOCR | 只在"无文本层"时才调用，量很小 |

**没有 Key 也能开发**：`LLM_MOCK=1` 时走 `core/llm.py` 的假响应，链路照样能通——这条保证"评测环境没网/没额度时系统不崩"，也是答辩可讲的鲁棒性设计。
