## 三、网盘包结构建议

```
SciAgent-省赛提交-章璞/
├── 01_技术文档.pdf                  ← docs/技术文档.pdf
├── 02_演示视频.mp4                  ← 待录制，1920×1080 / H.264
├── 03_作品介绍.md                   ← docs/作品简介.md（取需要的长度）
├── 04_截图/                         ← docs/交付材料/截图/*.png（12 张）
├── 05_源码说明.txt                  ← 仓库地址 + tag + 本地运行三条命令
└── 06_环境配置说明.txt              ← .env 需要填哪些键（不附真实 key）
```

> 打包时**不要**放：`.env`（含真实 key）、`deploy/`（含打包时的服务端口令）、
> `docs/qa/evidence/`（几百 MB 的中间证据）。评委需要复现时走仓库 + `.env.example`。

## 四、提交前 10 分钟检查

1. 公网链接在**手机 4G**下打开一次（不要带自己电脑的缓存）：应出页面，不是 403 白屏
2. 后台口令能进：`/admin` → 参数中心能读到 30+ 项
3. 仓库首页 README 里的**截图**和当前版本一致（改过界面就换图）
4. 仓库 tag `v1.1` 指向的提交 = 最终演示的代码（`git log --oneline -1` 对一下）
5. 视频能播放、有声音、时长在 5–8 分钟之间
6. 技术文档 PDF 页数 ≤30，封面信息（姓名/编号/组别/学校）无误
7. 提交后**不得修改**——点提交前把网盘里的包再下载一遍解压看一次

## 五、评审期间保持在线

- 平台实例默认会休眠，冷启动 10–30 秒（页面会自动显示"正在唤醒模型与索引"）
- 保活：`ops/cloudflare/worker.js` 需要粘到 Cloudflare Worker（`sci.zp-avatar.cn` 子域可选）；
  GitHub Actions 的 `schedule` 实测 35–46 分钟才触发一次，**不能当作 5 分钟保活**
- 最稳的做法：评审开始前 1 天手动打开一次，之后每天点一次链接
