# 翻译质量评测：现状体检 + 10 个模型横向对比

> 2026-11-13 ｜ 全部数据可用 `tests/trans_bench.py` 复跑，原始结果在 `data/trans_eval/`
> （`report.md` 自动生成、`summary.json` 汇总、`raw_<模型>.json` 逐段译文、`audit.json` 现网体检、
> `judge.json` 盲评明细）。

## 0. 一句话结论

1. **现网译文整体可用**：145 段正文里只有 2 段有硬伤（1.4%），1 段退化成一个 `5`、1 段正文漏译；
   数字/年份丢 23%、但抽查几乎全是章节号与图坐标刻度，实义小数只丢 2%。
2. **10 个模型横向比**：客观指标（数字保真、引用保真、术语命中、回译相似度）彼此差距 **< 3 个百分点**，
   没有"换一个模型质量翻倍"这回事；真正的差距在**用词与格式**——裁判挑错数从 0.94 到 1.94 处/段不等。
3. **不换交互路径的默认模型**：`qwen-flash` 每段均摊 1.1 秒（4 段一批约 4.4 秒，3 批并发）、指标与旗舰同级，边滚边读靠它。
   但「整篇翻译」是后台任务、用户本来就在等，于是新加 `TRANS_MODEL_HQ=qwen3.8-max`：
   只在整篇翻译/整篇译英时启用，裁判挑错少约 40%，代价是慢一倍多。
4. 修掉 3 个实测出来的问题：**退化译文被永久缓存**、**整句正文被当成公式不译**、**图注丢冒号**。

## 1. 输出可读性走的是哪条路（官方 1.3.3.2.b）

官方给了两条路：① 输出 Markdown/HTML 在网页里重排；② 输出 PDF 回填原位置。
**本项目走 ①，没有做 ②**，三个出口：

| 出口 | 形态 | 说明 |
| --- | --- | --- |
| 对照视图 | 网页内左右两栏 HTML | 左原文段落、右中文译文，逐段对齐；滚动联动、点段落跳回 PDF 原页（锚点用 chunk bbox，与问答引用共用同一坐标系） |
| 导出中译 | Markdown | 按章节分节；公式/代码用围栏原样保留；参考文献保留英文；可被任何 Markdown 渲染器重新排版 |
| 整篇译英 | Markdown | 中文论文→学术英文，同样按章节分节，产出 `{doc_id}_en.md` |

**为什么不做 ②（PDF 原位回填）**：中英长度比不同（同一段中文约占英文的 0.55–0.65 倍），
回填原 bbox 只有两种结果——大片留白或溢出压字，必须重新断行重排；而重排 PDF 还要嵌入 CJK 字体
（几十 MB），且现有锚点体系（`p3@x0,y0,x1,y1` 直接指向原 PDF 页上的一块）会全部失效，
对照视图与问答引用溯源就得再建一套坐标系。收益是"看起来像原版"，代价是丢掉本项目最硬的
"点引用回原文"能力，不划算。

**c 项（代码和公式保留英文）**：`keep_verbatim()` 判 "参考文献 / 公式块 / 代码块" 即原样保留、
不送模型——但 `formula` 这一档还要再过一遍"是否成串小写英文词"（见 §2 的 D-89，
解析器会把整句正文误标成公式）；导出时放 ```` ``` ```` 围栏，避免 Markdown 把 `$...$` 当数学渲染。

## 2. 现网译文体检（不调模型，纯本地对账）

对象：库里已缓存的 252 条译文（`qwen-flash` 193 条 + 原样保留 59 条），其中**值得翻译的自然语言正文 145 段**。
作者名单、arXiv 页眉、脚注 URL、公式块先排除（48 段）——它们原样保留是对的，算进"未译"只会制造假警报。

| 指标 | 结果 | 判读 |
| --- | --- | --- |
| 整段英文残留（>35% 英文词） | **5 段（3.4%）** | 其中 3 段是"本就不该翻"（配置表键值、作者块×2），真问题 2 段 |
| 实义小数/百分数丢失 | **3 段（2.1%）** | 两段是表格/图注里的 `1.7`、`5.1` 之类的编号，一段是正文 |
| 整数丢失 | 34 段（23%） | 抽查 20 段：28 段是章节号（`3 Skip-thoughts`）、图坐标刻度（`60 40 50 Epoch`）、页码。掉得不影响阅读 |
| 引用角标丢失 | **1 段** | `[2016]` 年份角标被吞 |
| 重复译文 | 0 段 | 该指标此前把"原样保留"的公式算进去，误报 6 段，已排除 |
| 退化译文（原文 ≥80 字而译文 <15 字） | **1 段** | LayerNorm p5 整段译文落库成 `"5"` |

**两个真问题（已在代码里修掉）**：

- **退化输出被永久缓存**：一批四段里模型对其中一段只回了个页码 `5`，段数校验通过 → 落库 →
  用户看到右侧只有一个 `5`，而且**再也不会重试**（chunk 已有译文）。
  修法：`_degenerate()` 判"原文 ≥80 字而译文 <15 字"直接丢弃不落库，下次进入该页自动重译。
  门槛用绝对长度会误伤标题/表注（`表 1：模型架构。`），所以只在原文足够长时才拦。
- **整句正文被当成公式、原样保留不译**：解析器把夹着希腊字母的句子标成 `formula`，
  `keep_verbatim` 只看 kind 就直接放行。实测 61 条原样保留里 5 条是完整句子，例如
  *"We used the Adam optimizer [18] with β1 = 0.9, β2 = 0.98 and ϵ = 10−9."*
  修法：`kind=formula` 也过一遍"成串小写英文词"判据（≥8 个即认定是正文），真公式里没有这种词串。

### 2.1 改后复测（26 页用新提示词 + `qwen3.8-max` 重译）

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 正文段数 | 145 | 157（+5 段原先被误判成公式、+7 段新覆盖） |
| 实义小数/百分数丢失 | 3 段 | **0 段** |
| 引用角标丢失 | 1 段 | **0 段** |
| 整数丢失 | 34 段 | 14 段（仍全是章节号、图坐标刻度） |
| 整段英文残留 | 5 段 | 6 段，但**逐条看全是"本就不该翻"**：配置表键值、两段作者块、基准测试名清单（Hellaswag/PIQA…）、一条公式碎片 |
| 退化译文（`"5"`） | 1 段 | 0 段 |

即：**能自动判定的硬伤已经清零**，剩下的都是"原文本来就不该被译成中文"的东西。

## 3. 多模型评测怎么做的

### 3.1 语料

17 段**真实论文段落**（不是造的例句），从库里 5 篇文献抽取，覆盖易翻车的地方：

| 段落 | 出处 | 考什么 |
| --- | --- | --- |
| attn-abs / attn-ref / attn-def / attn-mh | Attention Is All You Need | 摘要长句、引用密集（`[31, 2, 5]`）、定义句、变量密集（`dmodel/dk/dv`） |
| ln-abs | Layer Normalization | 与 batch normalization 的术语对照 |
| lora-notation / lora-math | LoRA | 符号声明（`Wq/Wk/Wv/Wo`、秩 `r`、`dffn = 4 × dmodel`）、含 `W0+∆W=W0+BA` 的分段 |
| scal-factors / scal-compute | Scaling Laws | 三因子 N/D/C、固定算力预算长句 |
| gpt3-intro | GPT-3 | 预训练/微调术语、`175B` 这类数量级 |
| dsr1-mixing / llava-intro | DeepSeek-R1 / LLaVA | 抽象名词密度、机翻腔最易露馅 |
| udl-caption / lora-table | 两篇的图注、表注 | 「图 N：」「表 N：」格式、符号保留 |
| zh-abs / zh-method / zh-exp | 中文论文 | 中译英（官方 1.6.4） |

段落经 `strip_carry()` 剥掉分块重叠尾巴，与生产送入模型的文本完全一致。

### 3.2 参评系统（10 个）

`qwen-flash`（当前默认）、`qwen3.7-flash`、`qwen3.8-flash`、`qwen-plus`、`qwen3.8-max`、
`deepseek-v4.1-flash`、`deepseek-v4-pro`、`glm-5.3`、`kimi-k3.1-pro`、`qwen-mt-plus`（专用机翻）。

**四个模型是"改参数才跑通"的**，这本身是结论：生产代码的调用姿势（system 提示词 + `temperature=0.1`
+ `enable_thinking=false` + 只收 user 消息）不是谁都吃：

| 模型 | 直接调用的报错 | 跑通需要 |
| --- | --- | --- |
| `glm-5.3` | `enable_thinking is restricted to True` | 强制开思考（本评测按此跑，成本上不划算） |
| `kimi-k3.1-pro` | `Parameter 'temperature'=0.1 is not supported` | 去掉 temperature |
| `qwen-mt-plus` | `Role must be in [user, assistant]`（拒 system） | 只发 user + `translation_options`，且**一段一次、输出纯文本**，与批量 JSON 协议不兼容 |
| `MiniMax-M3.1-Flash`、`stepfun/step-5-preview` | `The product is not activated` | 账号未开通，本轮无法参评 |

### 3.3 指标

**客观四项（脚本自算，与模型无关）**

- 数字保真：原文数字（含小数、百分数）有多少出现在译文里；上标/下标数字先归一化，
  `175B → 1750 亿` 这类本地化换算视为保真（否则会把正确译文判成错误）。
- 引用保真：`[27]`、`[31, 2, 5]` 是否原样保留。
- 术语命中：人工术语表（每段 3–5 个核心术语）是否用了通行译法，允许一组同义写法。
- 英文残留 / 长度比：抓漏译与"半中半英"。

**模型两项（都用不参评的模型，避免自夸）**

- 回译相似度：把译文用 `qwen3.6-plus` 译回英文，与原文算向量余弦（`qwen3.7-text-embedding`）。
- 盲评：`qwen3.7-max` 当裁判，**译文匿名成 A–H、顺序每段随机**，按忠实/术语/流畅/格式各 1–5 分，
  并要求列出具体错误（漏译/错译/术语/数字/公式/格式/机翻腔）。

### 4.1 总表（17 段平均）

| --- | --- | --- | --- | --- | --- | --- | --- | --- |

### 4.2 怎么看这张表

- **客观四项几乎打平**。10 个模型的回译相似度全在 0.959–0.973，术语命中 0.935–0.974，
  数字保真 0.962–0.986。也就是说：**"意思有没有跑"这一层，这批模型都过关**，
  差异落在 2–3 个百分点内，单看某一篇的某一页很容易得出相反结论。
- **差距在"读起来像不像中文论文"**。裁判挑错数从 0.94 到 1.94 处/段，翻了一倍。
  错误类型高度集中：**术语**（用词选择，例如 `dominant` 译"主导"还是"主流"）与
  **格式**（图注漏冒号、正文塞满英文括号）占了 70% 以上。
- **专用机翻模型不是最优解**。`qwen-mt-plus` 英文残留最低（0.025，几乎不夹英文），
  但**错译最多（7 次）**，且术语命中垫底（0.935）。它把 `E2E NLG Challenge` 展开成
  "E2E 自然语言生成挑战"——读者反而找不到原文里的那个缩写。
- **越贵不一定越好**。`glm-5.3` 必须开思考才能跑，每段均摊 6.1 秒（5 倍于 qwen-flash），
  客观指标还略低（数字保真 0.962）。`deepseek-v4.1-flash` 最快（0.9s）但机翻腔挑错最多（8 次）。

### 4.3 逐段能看出什么（举例）

同一段图注，四家的差别集中在格式与"是否多塞英文"：

| 模型 | 图 2.1 图注（节选） |
| --- | --- |
| qwen-flash | `图 2.1 线性回归模型。对于给定的参数 ϕ = [ϕ0, ϕ1]…` ← **冒号丢了** |
| qwen3.8-max | `图 2.1：线性回归模型。对于给定的参数选择 ϕ = [ϕ0, ϕ1]…` |
| deepseek-v4-pro | `图 2.1：线性回归模型。对于给定的参数选择 ϕ = [ϕ0, ϕ1]…` |
| qwen-mt-plus | `图2.1 线性回归模型。对于给定的参数 ϕ = [ϕ0, ϕ1]…` ← 冒号与空格都丢 |

摘要首段则暴露"过度注释"这个通病：`qwen-plus` 写成
"主流的序列到序列转换（sequence transduction）模型均基于编码器-解码器（encoder-decoder）架构下的
复杂循环神经网络（RNN）或卷积神经网络（CNN）"——四个括号注释，中文读者反而被不断打断；
`deepseek-v4-pro` 写成"主流的序列转换模型基于编码器-解码器架构中的复杂循环或卷积神经网络"，
同样忠实，读起来是中文。裁判把前者记为"增译/格式"，后者给了满分。

## 5. 结论与落地改动

### 5.1 模型选择

| 场景 | 模型 | 理由 |
| --- | --- | --- |
| 滚动阅读 / 划词 / 悬停（交互） | `qwen-flash`（不变） | 约 1.1s/段（一批 4 段并发 3 路）；术语命中最高（0.974）、数字保真与旗舰持平。换 plus/max 只换来 0.1–0.2 裁判分，却慢 2–3 倍 |
| 整篇翻译 / 整篇译英（后台） | **`qwen3.8-max`（新增 `TRANS_MODEL_HQ`）** | 用户点了就在等；裁判挑错 1.12 vs 1.81、流畅分 4.50 vs 4.31，慢一倍可接受 |
| 备选（想少一个模型依赖） | `deepseek-v4.1-flash` | 0.9s/段、数字保真 0.986，但机翻腔偏多，适合"只求快" |

代码：`app/core/config.py` 新增 `trans_model_hq`，`translate_pages(..., hq=True)` 只在
`start_job()`（整篇翻译）与 `_run_en_job()`（整篇译英）里启用；交互路径一行没动。
后台控制台可在「场景模型 → 整篇翻译模型」里改，留空即回退到 `trans_model`。

### 5.2 提示词与兜底

1. `_SYS` 第 3 条改严：普通名词短语**不再**加英文括号，只有缩写/专名与原文自带括号才保留
   —— 直接针对裁判记录最多的"英文残留/增译"。
2. 新增 `_fix_caption()`：图注/表注统一成「图 N：…」，模型漏冒号由代码补，不再靠提示词赌。
3. 新增 `_degenerate()`：退化成 `"5"` 这类短到不合理的译文不落库，下次进页面自动重译。
4. `keep_verbatim(kind="formula")` 增加"成串小写英文词"判据，整句正文不再被当公式跳过。
5. `scripts/retranslate_cached.py`：把库里已译的 26 页用新提示词 + `qwen3.8-max` 重译一遍，
   避免同一篇里新旧两种风格并存。

## 6. 已知取舍与没做的事

- **评测集只有 17 段**。够看出"格式/术语"这类系统性差异，不足以给小数第三位排名；
  裁判打分本身有 ±0.2 的抖动，表里 4.33 与 4.36 的先后不该当真。
- **回译相似度区分度低**（全部 0.96+）。它只适合当"有没有跑偏"的守门指标，
  不适合排序——这也是为什么结论主要依据"裁判挑错数 + 逐段人读"。
- **术语表是人工写的**（每段 3–5 个），只覆盖这批论文的核心术语；换一批文献要重写。
- **仍会漏掉"章节号/图坐标刻度"**：这类数字被模型自然忽略，对阅读无害，
  但如果将来要做"数字级溯源"，得先把图表刻度从正文块里拆出去。
- **数学密集页仍有"公式碎片被当正文送译"**：解析层会把某些公式行标成 `kind=text`
  （例如 `χi χi j Cov[yi, yj | x] φ2`），模型只能给出中英混排的碎片译文。
  这是解析侧的问题，靠翻译层打补丁容易误伤正常短句，本轮没动；
  真要修应该在 `app/parse/` 里把"符号密度高且无成句词"的块归到 formula。
- **专用机翻模型未接入生产**：`qwen-mt-plus` 一段一次、输出纯文本，与本项目"批量 JSON + 落库缓存"
  的协议不兼容，改造收益不抵成本（而且它错译最多）。
