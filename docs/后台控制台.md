# 后台控制台（参数中心）

入口：主界面右上角 **控制台**，或直接访问 `http://127.0.0.1:8013/admin`。

## 为什么要有这个东西

`.env` 适合"部署时定一次"，不适合"演示现场改一下"。答辩/评审时最常见的问题是：
检索结果不对，想调 `top_k`；翻译太慢，想换模型；接口报错，想确认 key 有没有生效——
这些都不该靠改文件 + 重启进程来解决，也不该靠猜。所以做一个参数中心，把每项参数
的**作用、范围、生效方式、来源**都摆出来，改完能立刻在"连通性自测"里验证。

## 口令与登录

后台默认要口令。口令只从环境变量读，写在 `.env`：

```ini
ADMIN_PASSWORD=<ADMIN_PASSWORD>
```

- 打开 `/admin` 先看到登录卡片，输错提示「口令不正确」，不会告诉你"差几位"。
- 登录成功后签发**随机会话令牌**，存在 `HttpOnly` Cookie 里，有效期 12 小时；
  服务重启后所有会话失效，需要重新输入。
- 连续错 8 次，同一 IP 锁 10 分钟（`app/core/auth.py` 里的 `MAX_FAILS / FAIL_WINDOW`）。
- 未登录时所有 `/api/admin/*` 一律 401；`/admin` 本身只是一张空壳页面，不含任何数据。
- 把 `ADMIN_PASSWORD` 留空则不校验（仅本机开发），登录页会明确显示"未启用口令"。

改口令：改 `.env` 的 `ADMIN_PASSWORD` 后重启进程。会话令牌存在进程内存里，
所以多 worker 部署时要么加粘性会话，要么改用 Redis 存令牌——本项目默认单 worker。

| 分组 | 项数 | 说明 |
| --- | --- | --- |
| 云端模型 | 8 | 接口地址、模型名、Key、temperature、最大输出、超时、路由策略、模拟开关 |
| 本地模型 | 3 | Ollama 开关、地址、模型名 |
| 场景模型 | 9 | 翻译模型 / 批大小 / 并发 / 页数上限、写作模型 / 输出上限、视觉模型三项 |
| 检索与索引 | 14 | top_k、重排保留数、混合权重 α、分块字数与重叠、向量化方式/模型/维度、向量库、重排方式/地址/模型/Key |
| 服务与安全 | 4 | 上传上限、日志级别、演示令牌、端口 |

## 四个关键设计

**1. 每项都标"生效方式"**，避免"改了没反应"的错觉：

| 标记 | 含义 |
| --- | --- |
| 立即生效 | 下一次请求就用新值（`top_k`、`temperature`、模型名…） |
| 仅影响之后入库 | 分块参数只对之后上传的文献生效，已入库的块不动 |
| 需重建索引 | 向量化方式 / 维度 / 向量库，改完要重新跑一次向量化 |
| 需重启进程 | 端口这类进程级配置 |

**2. 覆盖值单独存表，不写 `.env`。** `app_settings` 表只存"改过的项"，
界面明确标出来源（后台覆盖 / .env / 默认值）。这样回滚不会互相打架，
也能一眼看出"这个值是谁定的"。

**3. 恢复默认 = 回到启动时的 `.env` 值**，而不是代码里的出厂值。
这一点很关键：如果按出厂值恢复，点一下"全部恢复默认"就会把 `.env` 里配的
API Key 和模型名一起清空，服务当场失联（实测踩到，见 D-49）。

**4. 密钥永不回显。** GET 只返回"是否已配置 + 掩码"，PUT 时留空表示不修改。
导出配置也会跳过密钥类参数。

## 三个实用功能

- **连通性自测**：用当前保存的配置真打一次模型，回报路由、耗时、token 用量与回复。
  空回复会直接给出诊断（推理型模型把预算用在思维链上，`max_tokens` 太小），
  不用去翻日志。
- **导入导出**：导出 JSON 便于迁移/留档；导入走同一套校验，任何一项非法则整批拒绝。
- **审计**：改参数、恢复默认、删除文献都写 `audit_logs`，界面上能看到时间和操作者。

## 保活心跳（默认开）

服务启动时起一个 asyncio 循环，每 5 分钟做一次心跳，两件事：

1. `SELECT 1` 刷新数据库连接（空闲久了 SQLite/连接池会冷）；
2. 本地路由下给 Ollama 发一次空请求并带 `keep_alive=30m`，**让模型留在显存**。

Ollama 默认 5 分钟没请求就把模型卸掉，下一次请求要重新加载——实测同一台机同一模型：
冷 5876ms、热 138ms。演示时第一句话突然卡 6 秒，看起来就是"系统很慢"，而它只是被卸载了。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 后台保活 | 开 | 关掉后不再心跳，模型会按 Ollama 默认策略卸载 |
| 保活间隔 | 300 秒 | 必须小于 300，否则模型会先被卸掉再预热，等于白做 |
| 预热本地模型 | 开 | 不产生 token 费用 |
| 预热云端连接 | 关 | 每轮 1 token，一天 288 次，只省首次 TLS 握手；默认关 |

状态在「运行概览 → 模型与检索 → 保活心跳」看：`每 300s · 已跳 N 次 · 最近 Xms`；
异常时后面带一个红色「异常」标签，鼠标悬停看原因。也可以直接查接口：

```bash
curl -s http://127.0.0.1:8013/api/keepalive
curl -s -X POST http://127.0.0.1:8013/api/keepalive/beat   # 手动补一次，30 秒内幂等
```

**要不要再加系统 cron？** 一般不用——进程内循环随服务启停，不会留下孤儿任务。
只有在"服务跑在别的机器、本机想兜底"时才需要外部节奏，用 `scripts/keepalive.py`：

```bash
# Linux / macOS crontab
*/5 * * * * cd /path/to/sciagent && .venv/bin/python scripts/keepalive.py >> /tmp/scia.log 2>&1
```
```bat
:: Windows 计划任务（每 5 分钟）
schtasks /Create /SC MINUTE /MO 5 /TN SciAgentKeepAlive /F ^
  /TR "<repo>//.venv//Scripts//python.exe <repo>//scripts//keepalive.py"
```

## 校验规则（后端口径）

- 全部参数**先校验再落库**：10 项里 1 项不合法，整批拒绝，不留中间态。
- 整数/浮点带上下限，枚举限定取值，字符串限长 400。
- 未知键直接拒绝（防止打错字静默无效）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/params` | 参数定义 + 当前值 + 来源（密钥只给掩码） |
| PUT | `/api/admin/params` | 保存（整批校验，返回 applied / need_restart / need_reindex） |
| POST | `/api/admin/params/reset` | 恢复默认（keys 为空则全部） |
| GET | `/api/admin/overview` | 语料规模、存储占用、模型与向量库状态、运行时、最近审计 |
| POST | `/api/admin/test-model` | 真实调用一次模型，返回耗时与 token |
| GET | `/api/admin/export` | 导出覆盖项（不含密钥） |
| POST | `/api/admin/import` | 导入覆盖项 |
| GET | `/api/admin/audit` | 审计记录 |
