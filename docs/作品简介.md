# SciAgent 作品简介（三种长度，按表单空格选一段粘）

> 三版都用同一套事实，只是信息密度不同。数字取自当前语料：38 篇 / 19,970 块 / 221 条互引边。

## 一句话版（约 30 字，用于列表/标题）

SciAgent：答案能点回原文的科研阅读智能体——从读论文、查表格，到画出引用图谱、直接开写。

## 100 字版（用于简介栏）

SciAgent 是一个面向科研阅读的智能体。它把 PDF 里的版面、公式、表格拆成可检索的知识块，回答问题时每条结论都能点回原文那一段；遇到"库里没有"会直接说不知道。在此基础上还做了引用图谱、中英对照和写作助手：从读到写是一条闭环，而不是四个互不相干的工具。

## 400 字版（用于作品介绍正文）

读论文的真实困难不是"找不到 PDF"，而是三件事：**答案说不清出处**、**表格和公式读不出来**、**读完想写要从零开始**。

SciAgent 针对这三点做了一条完整链路。入库阶段按版面重建阅读顺序，把双栏、跨页表格、公式还原成结构化知识块（当前语料 38 篇论文、19,970 块）；问答阶段用「向量 + BM25」混合召回再交叉编码器重排，并强制模型只依据证据作答，每个结论都带可点击的 [n]，点一下直接跳到 PDF 那一页、框住那句话——不是给出一个"看起来像"的引用。证据不足时它明确说"库里没有"，而不是编一个。

针对表格，解析层按单元格的几何位置重建了列结构，检索层给表格块保留独立名额，所以"自注意力每层的计算复杂度是多少"这类只能看表的问题能答出 O(n²·d) 并指明是 Table 1 的哪一行。

此外还有：引用图谱（38 篇之间 221 条互引边，按 PageRank 分出基石/桥接论文，可一键生成领域综述）、版式阅读器（文本层可选、公式渲染、中英对照同步滚动）、写作助手（一句话想法出框架，References 全部来自库内真实文献，架构图接着大纲画，图表图注里的数字逐个回查原表）。

工程上：FastAPI + SQLite + 混合检索，无前端构建链；40 条回归用例、40 条单测、47 项接口巡检全部通过；一条命令本地复现，公网实例可在线体验。

## 800 字版（用于需要展开的场合）

（前置同 400 字版前三段，另补以下两段）

**为什么这些细节值得做。** 通用大模型读论文，最容易出问题的地方不是"不懂"，而是"懂个大概就开始编"。我们的做法是把"不许编"变成机制而不是嘱咐：检索阶段保证证据真的被召回（表格块单独保留名额、候选池按 top_k×4 扩张）；生成阶段把证据编号写进提示词结构，要求每个论断后标 [n]；生成后再做一次引用校验，越界编号、库里不存在的条目一律拦下。写作助手里进一步做了"References 只从库内元数据拼、模型只负责写论述"，所以参考文献不会出现编造的条目，正文里的 [n] 点得开、跳得到。

**这套东西是怎么被验证的。** 项目自带一套可复跑的测试：40 条按赛题考点组织的回归用例（覆盖双栏/扫描件/百页长文档、10 条引用逐条回原文核对、并发入库不串档、图谱与图表格式一致性等）、40 条单元测试（锚点、切块、表格网格、数值搬运）、47 项接口巡检，以及针对图谱交互、写作分步、后台参数热生效的专项脚本。缺陷台账记录了 77 条问题及修法，其中若干是自测才暴露的：整篇翻译因同名 Pydantic 模型覆盖而从未成功、WAL 模式下打包丢数据、前端依赖 CDN 导致国内白屏。这些都不是"功能没写"，而是"链路没被验证"——所以最后补的不是功能，是把每条链路都跑一遍。
