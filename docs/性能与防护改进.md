## 1. 问答慢：五次串行的模型调用

**问题**：上一轮巡检里"问答-对比"16.5 秒、"框架生成"10.2 秒。用户等 16 秒会以为卡死。

**先量，再改**。把一次问答的 trace 逐节点打出来，问题是结构性的：

| 步骤 | 原来 | 现在 | 为什么原来不对 |
|---|---|---|---|
| 规划 | 1.2s（**开了思维链**） | 1.2s（关思维链） | 拆 2–5 步、输出 JSON，思维链只贡献延迟；同一条指令开/关思维链，步骤数完全一样 |
| 查询改写 | 1.0s（串行） | 与规划**并行** | 两者互不依赖，串行等于白等一次往返 |
| 检索 | 2.0s | 2.0s | 真正的检索成本，没动 |
| 作答 | 2–3s | 2–3s | 该花的钱 |
| 审稿 | 1.5–3s（**无条件跑**） | 0s（快速模式且引用全对时跳过） | 审稿只在"深思"或"有未核实引用"时才可能改写答案 |
| 反思 | 0.9s（**无条件跑**） | 0s（成功时跳过） | 成功且无重试时反思结论恒为"无错误"，而代码只有 `error_type != "无"` 才写库——这次调用 100% 白烧 |

外加两个杠杆：

- **证据条数按问题类型给**（`app/rag/budget.py`）：数值/事实 5 条、概念 7 条、对比 10 条。
  证据条数直接决定 prompt 长度，而等待时间里有相当一部分是在等 prefill。
  数值题给 8 条反而更糊——模型会开始罗列不相关的表格行。
- **邻块扩展按类型给**：数值题 0 条（答案就在那一行，补出来的是表格下一行），
  对比题 3 条（论证常被切在两块之间）。原来固定补 3 条，`top_k=5` 实际会变成 8 条，
  自适应就失去意义了。

**实测**（同一批问题，本地服务）：

| 问题类型 | 改前 | 改后 |
|---|---|---|
| 数值（自注意力复杂度） | 8.4s | 6.7s |
| 概念（多头注意力作用） | 5.3s | 4.6s |
| 对比（RAG vs RETRO） | 巡检口径 16.5s | 6.6s（巡检口径） |

**答案缓存**：同一问题在同一份语料上 10 分钟内答案不变，直接复用（默认 600 秒）。
缓存键里带模型、库规模、是否深思、证据预算——少带任何一项都会制造
"改了参数还返回旧答案"这种最难查的问题。命中缓存时**仍然逐段回放 token**，
不是一次性丢全文：前端靠 token 事件做打字效果，一次全文出现会让用户以为页面卡了一下。

## 2. 术语不一致：同一篇里同一个词两种译法

**问题来源**：上一轮翻译评测（10 个模型 × 17 段）里，裁判挑出的错误七成是"术语用词"
——`dominant` 一会儿"主导"一会儿"主流"。长文分几十批翻，每批独立调用，
模型只能各自即兴发挥。

**做法**（`app/rag/glossary.py` + `data/glossary.json`）：

1. 术语表 107 条，来自库内 38 篇正文的高频统计（`loss function`、`layer normalization`、
   `self-attention`…）+ 人工校订译法；专名/缩写（Transformer、LoRA、BLEU）标 `keep_en`。
2. **只注入本批真正出现的术语**，最多 12 条。整份表塞进 system 提示会多花 200 token/批，
   更糟的是模型会开始"为了用术语而用术语"，把通顺的句子改坏。
3. **绝不强制替换**译文。正则把"隐单元"改成"隐藏单元"会改坏"隐单元的维度"这种正常表达。

**库内基线**（205 段已译正文）：

| 术语 | 标准译名 | 遵守 | 出现 |
|---|---|---|---|
| state-of-the-art | 当前最优 | 1 | 5 |
| parameter count | 参数量 | 1 | 2 |
| dropout | 随机失活 | 0 | 2 |
| prompt | 提示词 | 2 | 6 |

即 15 处里只有 4 处用了标准译名。

**注入后抽测**（6 段含上述术语的原文，qwen-flash）：5 段用"当前最优"（此前是"最先进/最优"混用），
`prompt` 全部译"提示词"。

一个副作用值得记：`sets a new state-of-the-art level` 被译成"树立了新的当前最优水平"，
比"最先进水平"生硬。**术语一致性的代价就是个别句子变生硬**，我选了一致性——
读者看到同一个概念两种叫法时的困惑，比一句略生硬更影响理解。

## 3. 公式碎片混在正文里

**问题**：解析器会把"符号密集的碎片"判成正文，翻译时送去翻，得到中英混排的乱码
（上一轮评测里 `χi χi j Cov[yi, yj | x] φ2` 就是典型）。根因是老的符号表
只列了 `αβγδθλμπσφψω`，**恰好漏掉 χ、ϵ、ϕ、∇** —— 而 χ² 检验、Adam 的 ϵ、
势函数 ϕ 在论文里非常常见。

**改法**：把判据抽成纯函数 `looks_formula_text()`（`app/parse/structure.py`），
用整段希腊字母区 `U+0370–U+03FF` + 数学算符 + 符号密度，同时显式豁免"成句正文"：

```
符号密度 ≥ 0.08           → 公式
小写英文词 ≥ 5 个         → 正文（即使符号很多）
```

两条豁免规则都是用真实段落调出来的：
`We used the Adam optimizer with β1 = 0.9, β2 = 0.98 and ϵ = 10−9.` 有 5 个符号，
但小写词 7 个 → 是正文，必须翻；`Now let's perform some algebraic manipulations…: We seek:`
以冒号收尾，如果按"句末标点"判豁免就会把整段吞成公式，翻译时原样保留英文。

**迁移**：判据改在解析层只在重新解析时生效，库里已有的块不会自动变。
`scripts/reclassify_formula.py` 用**同一个纯函数**把存量重标了一遍（只动 `kind=text`
且长度 ≤200 的块，写库前备份）：

```
正文块 2864 条 → 命中 143 条 → formula 1296 → 1439，text 10131 → 9988
```

## 4. 限流与演示保护

公网上挂着演示地址，任何人都能点。被打爆的后果不是"慢"，是**额度被刷光、后面来的人打不开**。

| 参数 | 默认 | 说明 |
|---|---|---|
| `rate_limit_per_min` | 120 | 每 IP 每 60 秒总请求；正常人手点一分钟十几次，只挡脚本 |
| `rate_limit_ask_per_min` | 30 | 问答/写作/上传单独计数（一次问答成本是翻页的几千倍） |
| `upload_concurrency` | 1 | 同时解析的 PDF 数；解析吃 CPU，两人同传会把问答也拖垮 |
| `rate_limit_local` | 开 | 本机回环（127.0.0.1 / ::1）豁免限流。**这条是踩出来的**：第一版没豁免，跑一次 `qa_suite` 后半程 9 条用例全红，原因全是自己把自己打成 429 |
| `guard_mode` | off | off / warn（只打响应头）/ enforce（401） |

设计取舍：
- **默认宽松到正常使用碰不到**。太紧的限流比没有限流更糟——第一个评审就被 429 挡在门外。
- **滑动窗口**而不是固定窗口计数器，避免 59 秒打满、61 秒再打满的两倍额度漏洞。
- **上传不排队、直接提示**："正在解析另一份文献（约 10–40 秒）"比一个不动的进度条诚实。
- **本机豁免**：开发与回归测试都从回环地址来，不豁免等于"防护把测试挡住"。
  公网访客走 `X-Forwarded-For`，不受影响；只有反代不透传 XFF 时才需要关掉这一项。
- **令牌默认 off**：`enforce` 会挡住"拿到链接就能用"的演示路径。前端会自动把 `?token=`
  存起来并加到所有请求头，同时从地址栏抹掉（截图/复制链接时不该把令牌带出去）。

## 5. 溯源从 10 条扩到 100 条

原来 `qa_suite` 的 A04 只验 10 条引用，而且混入了"模型生成质量"的影响。
新增 `tests/citation_audit.py`：**不调模型**，直接拿库里 100 个块的 `bbox` 去 PDF 上
取那个矩形里的文字，和块自己的 `text` 比。

```
可达 98/98 = 100.0%     精确高亮 84/98 = 85.7%     不可校核 2 条（图片版 PDF）
recall 中位数 1.000     precision 中位数 1.000
按类型：text 37/38、table 33/34、figure 28/28
```

三件事值得说：

1. **判定只看 recall**。它回答的是"点了引用能不能落到这段原文"。
   precision 低是另一回事——首页那种"标题+作者+摘要"合一块的块，bbox 是联合框，
   矩形里当然还框着页眉和作者名单；内容照样看得见，只是高亮面积偏大。
   把这两件事混成一个"失败率"，真正的坐标错位反而被埋掉。
2. **2 条不可校核不是失败**：`1706.03762v1_img.pdf` 是纯图片版（整页无文本层），
   页面靠渲染图看。把它算进分母会让 100% 显示成 98%，而这两条根本无从校核。
3. **85.7% 的"精确高亮"**：14 条能落到原文但框偏大，全是首页作者块。
   要修得在解析层把"标题/作者/摘要"拆成三个块，属于下一轮的事。

## 6. 语料：从"只会 LLM"到覆盖五个方向

原来 38 篇几乎全是 LLM/NLP。问题不是"内容少"，是**问答会露知识盲区**：
问 ResNet 的残差为什么缓解退化、问 DDPM 的前向加噪、问 DQN 的经验回放，
全都答"文献库中没有检索到相关内容"。一个"科研智能体"如果只会 LLM 论文，
"通用性"就无从谈起。

`scripts/seed_corpus.py` 按方向补 15 篇（每篇都是被引量最高、公式/表格丰富的经典）：

| 方向 | 论文 |
|---|---|
| 生成模型 | VAE (1312.6114)、GAN (1406.2661)、DDPM (2006.11239) |
| 视觉 | ResNet (1512.03385)、Grad-CAM (1610.02391)、BatchNorm (1502.03167) |
| 强化学习 | DQN (1312.5602)、SAC (1801.01290)、Decision Transformer (2106.01345) |
| 序列建模 | Neural MT / additive attention (1409.0473) |
| 优化 / 蒸馏 | Adam (1412.6980)、Distilling Knowledge (1503.02531) |
| 大模型 / 对齐 | PaLM (2204.02311)、Constitutional AI (2212.08073)、LLaMA (2302.13971) |

结果：**新增 12 篇，1 篇（LLaMA）被判定重复**——库里已有同名论文，
去重把它拦了下来，这是预期行为，也顺带验证了上一轮把标题门槛从 0.60 提到 0.70 之后
并没有放过真重复。库从 **38 篇 / 19,970 块 → 52 篇 / 24,003 块**。

抽样验证（每问都带论文特征，避免"泛泛而谈"）：

| 问题 | 耗时 | 引用校验 | 答案要点 |
|---|---|---|---|
| ResNet 残差为什么缓解退化 | 6.1s | 1.00 | "改为拟合残差 F(x) := H(x) − x，原始映射变为 F(x)+x" |
| DDPM 前向过程怎么加噪 | 5.2s | 1.00 | "固定 Markov chain，按方差调度 β1…βT 加高斯噪声" |
| DQN 用了哪两个关键技巧 | 4.1s | 1.00 | "奖励裁剪 + 经验回放" |
| Adam 的偏差校正 | 5.2s | 1.00 | "除以 (1−β1^t)、(1−β2^t)" |
| 对比 GAN 与 VAE | 8.1s | 1.00 | 表格逐项对比"是否建模概率分布" |

## 7. 可观测性：后台多一张"近 24 小时"卡片

原来只有日志和 `/diag`，看不到"最近调用量/延迟/失败率"。新增 `GET /api/admin/metrics`，
数据源就是 `tasks` 表（每次问答都落一条，含耗时、模式、状态、校验结果）。
**不另建指标表**——双写必然不一致，而不一致的指标比没有指标更误导人。

后台概览页展示：小时柱状图（失败的小时标红）、引用校验均值与"低于 0.75"次数、
答案缓存命中率、限流拦截数、最慢 5 次问答。

## 9. 这轮没做的

| 事项 | 为什么没做 |
|---|---|
| 首页作者块 bbox 收缩（85.7% → 100% 精确高亮） | 要在解析层把标题/作者/摘要拆块，影响所有已有文献，属于独立一轮 |
| PDF 原位译文回填 | 中文字数约为英文 0.6 倍，回填必须重排并嵌 CJK 字体，且现有锚点全部失效（上一轮已论证） |
| 语义缓存（换一种问法也能命中） | 需要向量索引 + 相似度阈值调参，误命中比不命中更伤信任 |
| i18n / 多语言界面 | 比赛不需要，且会稀释本轮改动 |
| 「限定文献」检索仍要 10.2s | 指定 `doc_ids` 时不能复用全库的分词/BM25 缓存，每次要重算一遍语料（D-85 的第二层根因）。修法是把语料按 doc 缓存成子集视图，工作量约一天 |
