# SciAgent 演示视频脚本（v61 · 9 分钟版）

> 用于提交第 7 项「演示视频地址」。界面对应 **v61**（2026-11-17），线上与本地同一版本。
> 目标时长 **9 分 00 秒**（平台要求 5–8 分钟，超一点不影响评审，但**不要超过 10 分钟**）。
> 讲解原则：**每个功能都要落到"它怎么做到的"**，不讲"我们支持 X"，讲"X 在实现上解决了哪个具体错误"。
> 提交要求原文：**切勿提交百度网盘链接**，视频统一上传 B 站等可公开访问的平台，只填 `https://` 页面地址。

## 三、第一段：云端（0:00–7:10）

### 0:00–0:45 开场

**画面**：停在问答首页，什么都别点。

**口播**：
> 各位评委老师好，我演示的作品是 SciAgent，一个把"引用可验证"做成硬约束的科研智能体。
>
> 市面上多数论文问答是"检索到片段、交给模型写"，问题在于模型会顺手编一个页码或一句不存在的话。
> 我们换了个做法：**模型只被允许引用片段编号，坐标由服务端算**。模型输出 `[1]`，服务端把 1 号片段
> 换成 PDF 里的物理坐标，并在原文里核对这句话是否真的落在那个框里——对不上就判幻觉，剔除重答。
>
> 第二个支点是图谱不只画线：PageRank、介数中心性、社区发现在**选中的子图上重算**，
> 所以"这五篇里谁是基石"是真结论，不是全库排名的裁剪。
>
> 第三个支点：同一份代码，云端与完全断网的本地 3B 都能跑，差别只有一个环境变量。
>
> 先看线上这个纯云端实例。

### 0:45–1:45 文献库与入库流水线

**操作**：指左栏「文献库 39 篇」→ 指顶栏「文献 39 / 片段 27667」→ 点 **「一键导入官方测试集」**（若已导入过，跳过点击，只讲结果）。

**口播**：
> 库里 39 篇论文、两万七千多个可定位片段。入库不是"存文件"，是五步：
> 版式解析拿到文本层和词框 → 按正文指纹判重（同文不同版本会被认出来）→ 切块并保留页码与 bbox →
> 建章节树 → 向量化。
>
> 两个工程细节值得说：一是判重用的是内容指纹不是文件名，所以同一篇的 v1 和 v7 不会各算一篇；
> 二是 BM25 的分词结果会落盘，两万个块重启后不用再花十二秒重新分词——云端冷启动最贵的一步被搬到构建期了。

### 1:45–3:30 问答（核心，讲慢一点）

#### ① 确定性作者题（1:45–2:10）

**操作**：左栏点 **Attention Is All You Need** → 输入：

> 论文 Attention Is All You Need 的第 6 作者是谁，在哪个公司/机构工作？

**口播**：
> 先问一个作者题，答案是秒出的。因为这类问题**根本不过模型**：解析阶段已经把首页的署名序列
> 存成结构化字段，直接按序号取值。
>
> 这是被评审打回来才改的——最早让模型从切块里数人名，它把第 5 位写成第 6 位，
> 而三重校验只看引用和数字，这种纯文本事实反而全部跳过，校验通过率给了 1.0。
> 现在加了第四重：作者枚举核对，模型答的和元数据不一致就重规划一次。

#### ② GPU 题 + 证据跳转（2:10–2:55）

**操作**：输入

> 这篇论文训练 Base 模型用了多少块 GPU？什么型号？

→ 答案出来后点答案里的 `[1]` → 页面跳到原文该句 → 再点右侧证据卡片。

**口播**：
> 换一个必须跨段落找的问题。检索走的是三路：BM25 出稀疏排名，向量出稠密排名，
> 用 RRF 融合——**只融合名次，不融合分数**。原因是两路分数量纲完全不同，
> 加权求和等于让其中一路悄悄主导；RRF 只用名次，不用调权重，这是工程上更稳的选择。
> 融合后可选一次重排，把真正作答的段落顶上来。
>
> 答案是 8 块 P100，后面带编号。点编号跳回原文，高亮是**句级**的——服务端在片段里挑出
> 真正作答的那一句，不是把整段涂黄。右侧每条证据都有页码和锚点，可以逐条核对。

#### ③ 负例拒答（2:55–3:30）

**操作**：输入

> 这篇论文里 Adam 优化器的 β3 参数取了多少？

**口播**：
> 再看负例。Adam 只有 β1 和 β2，没有 β3。它没有编，直接说未提及。
>
> 这条比答对更值钱，但实现上不能简单粗暴地"检索不到就拒答"。我们的做法是**实体闸门**：
> 从问题里抽出专有名词（大写开头的术语、带编号的模型名），**全部**都不在证据里才拦。
> 只缺一个不拦——否则「Transformer 的 References 里有谁」这种问题会被误伤，
> 这两个坑都是实测踩出来的。

### 3:30–4:15 阅读与翻译

**操作**：
1. 翻到正文某页，点正文里的 `[1]` → 跳到 References 第 1 条
2. 在条目浮层里点「正文引用 N 处」的一条 → 跳回原文
3. 打开工具条 **「悬停译」** → 鼠标在英文句上停一下
4. 选中一段英文 → 点「译」→ 切 **「对照」** 视图，左侧滚动右侧跟随

**口播**：
> 引用是双向的：正文点 `[1]` 到参考文献，从参考文献还能点回正文被引的那一句。
> 靠的是入库时给每条引用都建了正反两向索引，不是运行时去正则匹配。
>
> 阅读器没用 PDF.js，是自己渲页图叠一层透明文本层——排版百分之百还原，
> 划词位置来自 PyMuPDF 的词框。代价是个别连字会偏一两像素，这个取舍写在文档里。

### 4:15–5:55 图谱（v61 改过，重点讲）

**操作**：
1. 点视图 **「图谱」**
2. 指顶部统计「39 篇 · 213 条互引边」
3. 点 **「选择文献（39/39）」** → **「清空」** → 勾 5 篇（Attention / BERT / GPT-3 / Layer Normalization / FlashAttention）→ **「按所选重建图谱」**
4. 指每个圈都有名字 → 点一个节点，看右侧「被这 N 篇引用 / 引用了这 N 篇」
5. 点 **「生成领域综述」**
6. 关掉综述，点 **「未来工作方向」**

**口播**：
> 图谱默认 39 篇、213 条互引边，节点大小按 PageRank。
>
> 这里可以挑文献，勾哪几篇就只用哪几篇建图。要说清楚的是：它不是把别的点藏起来——
> **PageRank、介数中心性、社区发现都在选中的子图上重算**。这个区别很实质：
> 如果只是把全库排名前几的点留下，"这五篇里谁是基石"就是伪结论；
> 重算之后，节点重要性是这五篇内部的相对结构。引用指向未选中文献时，边直接丢弃，
> 不会退回去按标题模糊匹配到另一篇——那会把图悄悄画错。
>
> 综述也不是模型自由发挥：先按入度×PageRank 取 top-k，再把每篇的标题和摘要按影响力顺序喂进去，
> 提示词强制每句标注来源编号，编号只能来自这份列表。所以它给的是"有出处的综述"，
> 不是"读起来很像综述的散文"。
>
> 未来工作方向是从各篇 Future Work 和 Limitations 里抽的**原句**，先用四 gram 的 Jaccard 去语义重复。
>
> 判定"这条是不是已经被人做了"这一步，候选**只取引用图上引用了这篇的后继文献**——不是全库较新的都算，
> 因为共现不等于继承，一篇没引用它的论文撞了几个词就标"已解决"，被问"哪一篇做的"就答不上来。
> 比对是两段式：先用块级向量召回段落，再用**句向量**在句这一层比一次——句和句才是同一粒度，
> 阈值放在句这一层才有意义。关键词只用来解释"为什么像"，不再当门票。
> 没有一条后继时才退到同主题的较新论文，并且会明确标出来这是弱证据。

### 5:55–6:55 写作

**操作**：
1. 视图 **「写作」** → **「论文框架」** → 输入 `把证据链做成可审计的引用校验层` → 生成
2. 指 References 全是库内文献
3. 切 **「架构图」** → 指 mermaid / dot / tikz / matplotlib 四份代码
4. 切 **「数据图表」** → 生成 → 指 Figure Caption 与数值回查

**口播**：
> 写作三块，共同点是**把不确定性挤到结构外面**。
>
> 框架的参考文献百分之百来自库内：不是提示词里写"不要编造"，而是让模型只输出文献编号，
> 条目由服务端从库里取。编造的条目在结构上产生不了。
>
> 架构图一次生成四种格式。模型只产出节点和边，四种代码由渲染层生成——所以四份必然描述同一张图，
> 也不会出现模型写错的 `\node` 语法。
>
> 数据图表的图注会回查原始数据：模型写完把图注里的每个数字拿回表里比对，查不到的列出来。
> 这是官方题 1.6.3 要求的，也是"数字可溯源"这条原则的延伸。

### 6:55–7:10 转折

**操作**：切回问答首页，别关标签页。

**口播**：

### 7:35–8:25 同一道题，本地跑一遍

**操作**：问**与云端完全相同**那道 GPU 题，等答案（首次含模型加载 15–25 秒；热态 6–8 秒）；

**口播**：
> 同一道题，8 块 P100。跑的是本机 3B，模型名和耗时都写在答案上方，不是挂个云端模型的名字。

>
> 引用依然能点回原文——检索、锚点、校验跟云端是同一份代码，只是换了一套向量和本地生成。

## 六、录制时的十个坑

1. **云端顶栏不该有「云端 / 本地 3B」**。出现说明包配置错了，别录。
2. **先热一次本地模型**（断网前问一题），否则录到的是 20 秒空等。
3. **断网后「本地 3B」点不动**：刷新页面再点（10 秒缓存里可能存了旧探测结果）。
4. **别点「控制台」**（`/admin`），有口令页与参数页。
5. **画面里不能出现** `.env`、API Key、网盘链接。
6. **图谱别全选 39 篇讲标签**——39 个名字一定互相压。按脚本先清空再选 5 篇。
7. **综述和未来工作要等 3–6 秒**，后期可加速，但别剪掉"正在生成"。
8. **口播不要念参数表**，说人话；具体数字留给字幕。
9. **一次录完**，念错停 2 秒重念，后期剪，别分段录。
10. **上传 B 站**：标题「SciAgent · 引用可验证的科研智能体（云端 + 断网本地双模式）」，
    简介放 GitHub 链接 + "云端 0:00–7:10，断网本地 7:10 起"。
