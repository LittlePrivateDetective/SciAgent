# 微调实验（v1.1 收尾）

> 目标：把库里的论文变成指令数据，训一个"会按 SciAgent 规矩答论文题"的本地 3B 模型，
> 用可判定指标证明它到底变好了没有。本文只记录**实测数字**，不改主站默认路由。

## 1. 环境与配置

| 项 | 值 |
| --- | --- |
| 硬件 | RTX 2060 6GB / 15.9GB RAM / Windows 10 |
| 底座 | `Qwen2.5-3B-Instruct`（本地 5.8GB，不联网下载） |
| 训练方式 | 4bit QLoRA（nf4 + 双重量化），fp16 计算 |
| LoRA | r=16，alpha=32，dropout=0.05，7 个 target module（q/k/v/o/gate/up/down） |
| 可训参数 | 29,933,568 / 3,115,872,256（0.96%） |
| 数据 | `data/sft/train.jsonl` 280 条；`dev.jsonl` 28 条（由 qa 308 条按 90/10 拆分，**训练不碰 dev**） |
| 超参 | 1 epoch、batch 1 × 累积 8（35 步）、max_len 896、lr 2e-4、cosine、adamw_torch |
| 耗时 | **44 分 26 秒**（满显存时逐步变慢，约 20–107 s/步） |

## 2. 训练结果（v1：只训 QA）

- loss：**1.4572 → 0.6833**（7 个记录点，最低 0.6676）；`train_loss=0.855`。
- 产物：`data/sft/out/lora-3b/adapter_model.safetensors`（119.8MB）。
- 断点：`checkpoint-10/20/30/35`，`save_total_limit=2`。

## 3. 合并与部署（v1）

| 步骤 | 命令 | 结果 |
| --- | --- | --- |
| 合并 | `ml/merge_lora.py --lora ... --out data/sft/out/merged-3b` | **38 s**，fp16 5.75GB，4 分片，3,085,938,688 参数 |
| 转 GGUF | `convert_hf_to_gguf.py merged-3b --outtype f16` | **20 s**，6.17GB，434 tensors |
| 导入 Ollama | `ollama create sciagent-3b -f data/sft/Modelfile` | **52 s**，`sciagent-3b:latest`，6.18GB，F16，runner=llamacpp |

Ollama 实测（真实证据题，非"只回复 OK"）：

```
b和g是与ht同维度的偏置和增益参数[1]。其中，Whh是循环隐藏到隐藏权重，Wxh为底部输入到隐藏权重[1]。
总耗时 14.8 s / 44 tokens / 8.1 tok/s
```

## 4. 三列评测（v1，28 条 dev 题）

| 模型 | 引用率 | 引用越界率 | 数字出错率 | 元话语率 | 空答案率 | 平均字数 | 字/秒 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| base 3B | 0.500 | 0.036 | 0.071 | 0.000 | 0.000 | 71 | 13.6 |
| **微调 3B** | **1.000** | **0.000** | **0.036** | 0.000 | 0.000 | 71 | 7.6 |
| 云端 `deepseek-v4.1-flash` | 0.929 | 0.036 | 0.107 | 0.250 | 0.000 | 140 | 96.8 |

解读（只按硬指标，不请模型当裁判）：

- **微调把引用行为从"一半靠猜"拉到 100%**：base 有一半答案完全不写 `[n]`；微调后 28/28 全部带引用，且没有越界编号。
- **数字保真优于 base，也优于云端小样本**：3.6% vs 7.1% vs 10.7%。云端更爱扩写（平均 140 字），引入数字的风险更高。
- **元话语**：微调后 0%，云端 25%（"根据提供的证据"这类线上会判失败的话）。
- **速度**：微调后 7.6 字/s，比 base 慢一半。原因是模型更倾向于写满引用与完整句，EOS 来得晚；不是 adapter 的计算开销。云端 96.8 字/s，本地 3B 无法在速度上竞争。
- **拒答正确率无法评估**：`dev.jsonl` 28 条里 `deny` 全为 `None`（拆分时拒答样本都进了 train），所以这一列留空，不编造数字。

结论：**微调让 3B "守规矩"（引用、数字、拒答格式），但不可能在知识广度上追上云端**，与 README 里写明的边界一致。

## 5. 第二轮：QA + 翻译混合训练（v2）

第一轮只训了 QA（280 条），`trans.jsonl` 没进训练，模型不会做翻译。第二轮把翻译也纳入：

| 项 | 值 |
| --- | --- |
| 数据 | `train.jsonl` 280 + `trans_train.jsonl` 55；`trans_dev.jsonl` 8 条留出（按首段原文分组，防同段落泄漏） |
| 步数 / 耗时 | 42 步 / **16 分 47 秒**（335 条，batch 1 × 累积 8） |
| loss | **1.0497 → 0.6786**（min 0.5766，`train_loss=0.740`） |
| 产物 | `lora-3b-v2`（115MB）、`merged-3b-v2`（5.75GB）、`sciagent-3b-v2-f16.gguf`（6.17GB）、Ollama `sciagent-3b-v2:latest`（F16） |

### 翻译能力（8 条 dev，base vs v2）

| 模型 | JSON可解析率 | 条数匹配率 | 数字保真率 | 中文占比 | 英文残留率 | 字/秒 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| base | 0.750 | 0.375 | 0.875 | 0.622 | 0.125 | 17.0 |
| **v2** | **1.000** | **0.750** | **1.000** | 0.632 | 0.125 | 7.4 |

### 问答是否回退（28 条 dev）

| 模型 | 引用率 | 引用越界 | 数字出错 | 元话语 | 平均字数 | 字/秒 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| v1（只训 QA） | 1.000 | 0.000 | 0.036 | 0.000 | 71 | 7.6 |
| **v2（QA+翻译）** | 0.964 | 0.000 | 0.036 | 0.000 | 71 | 5.6 |
| 云端 | 0.857 | 0.000 | 0.107 | 0.107 | 141 | 87.9 |

结论：混合训练用 **3.6% 的引用率**换来翻译格式的全面改善（JSON 解析 +25pp、条数匹配 +37.5pp、数字保真 +12.5pp），QA 其他指标不变。翻译仍有短板：**8 条里 2 条把两段并成一段**（条数匹配 75%），需要 2 epochs 或更大 `max_len` 再试。

Ollama 实测（`sciagent-3b-v2`）：QA 19.4s/58tok 且带 `[1]`；翻译 20.7s/142tok，输出可解析 JSON，但同样出现 1/2 条合并。

## 6. 已知限制

1. **推理侧已从 F16 换成 Q8_0**（2026-11-15 补做）。此前卡在"Ollama 的 `--quantize`
   只对 safetensors 生效、safetensors 走 MLX 报 `unsupported MLX architecture: Qwen2ForCausalLM`、
   GGUF 又必须先量化、本机没有 cmake 构不出 `llama-quantize`"这条死链上。
   出路是 **`convert_hf_to_gguf.py --outtype q8_0`**——它本身就支持直接产出 8bit GGUF，
   不需要编译器：

   ```bash
   # 只需 llama.cpp 源码里的 Python 转换脚本，不用编 C++
   python convert_hf_to_gguf.py data/sft/out/merged-3b-v2 \
          --outfile data/sft/out/sciagent-3b-v2-q8_0.gguf --outtype q8_0
   ollama create sciagent-3b-v2-q8 -f data/sft/Modelfile.q8
   ```

   效果：3.28 GB / **100% 进显存**、**49 tok/s**（F16 时是 7.24 GB、43% 落在 CPU、9.1 tok/s），
   端到端一问 **12.5 s**（原 31–36 s）。质量未见退化（同一题引用校验 8/8）。
   想要更小还能走 Q4_K_M（约 1.9 GB），但那一步必须编 `llama-quantize`，仍受编译器限制。
2. **dev 没有拒答样本**，拒答正确率这一列无法评估；需要重新按 deny 分层抽样。
3. 训练数据 280 条、覆盖有限；换一批文献要重新造数据。
4. 满显存时训练步速从 20 s 退化到 107 s，属于 6GB 卡的硬边界。

## 7. 复现

```bash
# 训练
ml/.venv/Scripts/python.exe ml/train_lora.py \
  --data data/sft/train.jsonl --base ml/models/Qwen2.5-3B-Instruct \
  --save-steps 10 --out data/sft/out/lora-3b

# 合并
ml/.venv/Scripts/python.exe ml/merge_lora.py \
  --lora data/sft/out/lora-3b --out data/sft/out/merged-3b

# GGUF
ml/.venv/Scripts/python.exe <llama.cpp>/convert_hf_to_gguf.py data/sft/out/merged-3b \
  --outfile data/sft/out/sciagent-3b-f16.gguf --outtype f16

# Ollama（Modelfile 的 FROM 指向上面的 .gguf）
ollama create sciagent-3b -f data/sft/Modelfile

# 三列评测
ml/.venv/Scripts/python.exe ml/eval_ft.py --lora data/sft/out/lora-3b --cloud
```

> 产物都在 `data/sft/`（不进仓库）；底座在 `ml/models/`（不进仓库）。

## 8. 界面上怎么切到它（v1.1 增补）

本地模型原来只能在后台上把 `LLM_ROUTE` 改成 `local`——要开 `/admin`、输口令、
在 50 项参数里找路由策略，演示时评委看不到。v1.1 在头部做了**两个分段按钮「云端 / 本地 3B」**（绿色=本地生效）：

| 项 | 取值 |
| --- | --- |
| 出现条件 | `/api/system/info` 返回 `local.available=true`（开关打开 + Ollama 可达 + **模型名在 `ollama list` 里**）；公网实例没有 Ollama，徽标退化成只读标签 |
| 作用范围 | 只作用于**当次提问**：请求头 `X-LLM-Route` → 中间件写 contextvar → 本次请求内所有模型调用（含流式分块）都读它，响应结束即失效 |
| 不改全局 | 全局路由仍只在后台参数中心改。页面按钮若写全局配置，等于给公网留了一个"换掉所有人模型"的无鉴权写接口 |
| 只承诺问答 | 本地路由下 `_chat_ollama` 固定用 `OLLAMA_MODEL`，会覆盖 `TRANS_MODEL` / `WRITE_MODEL`；而 v2 的翻译条数匹配只有 0.75，所以切本地只用于问答，翻译/写作保持云端 |
| 缓存 | 答案缓存键加了 `route` 字段：否则先问本地、再问云端会命中那条短得多的本地答案 |

**实测（同一题「REALM 的检索器是怎么训练的？」，单篇 244 块）**

| 模式 | 耗时 | 回答标签 | 内容 |
| --- | ---: | --- | --- |
| 本地 `sciagent-3b-v2` | 22.5 s | `深思 · 本地 · 22.5s` | 397 字符，带 `[1] [2]` 与页码锚点 |
| 云端 `deepseek-v4.1-flash` | 3.6 s | `深思 · 3.6s` | 585 字符，引用更完整 |

换成 Q8_0 之后（3.28 GB，100% 进显存、49 tok/s），同一题从 **22.5 s 降到 12.5 s**；
在此之前用 F16（6.18 GB）时，6 GB 显存装不下，`ollama ps` 显示 **43%/57% CPU/GPU 分载**、
9.1 tok/s——那是"切到本地要等半分钟"的物理原因，也是当时默认仍走云端的理由。
回归脚本：`tests/ui_model_switch.py`（10 项断言 + 截图 `docs/qa/evidence/model_switch.png`），
无 Ollama 的一支用 `EXPECT_LOCAL=0` 跑。
